# Архитектура сайта ООО «ДОРТЕХ»

Версия 0.1 от 27.10.2026. Документ для согласования с Заказчиком до начала основной реализации (Приложение 3, этап «Подготовка и проектирование»).

## 1. Состав системы

| Компонент | Технология | Назначение |
|---|---|---|
| Веб-интерфейс | Next.js 16 (React 19, TypeScript, Sass), SSR | Публичный сайт, кабинет клиента, кабинет менеджера |
| Серверное приложение | Python 3.12, FastAPI, SQLAlchemy 2 (async), Alembic | REST API `/api/v1`, бизнес-логика, панель администратора |
| Панель администратора | starlette-admin 1.0 (русский интерфейс) | Каталог, тарифы, контент, пользователи, роли, журнал, импорт CSV |
| База данных | PostgreSQL 16 (+ `pg_trgm` для поиска) | Все данные сайта, очередь исходящих сообщений |
| Воркер | `python -m app.worker` | Отправка email (SMTP Заказчика) и webhook с повторами |
| Прокси | Caddy 2 | HTTPS (Let's Encrypt), маршрутизация, лимит размера загрузок |
| Контейнеры | Docker Compose | Два окружения (test, prod) на одном или разных серверах |

Соответствует ТЗ 5.3 (React + Python + PostgreSQL). Все зависимости — открытые лицензии (MIT/BSD/Apache), реестр передаётся по ТЗ 7.

## 3. Роли и доступ (ТЗ 1)

| Роль | Что видит и делает |
|---|---|
| Посетитель | Публичные разделы, каталог, сравнение, заявка без регистрации, форма контактов |
| Клиент | То же + кабинет: профиль организации, собственные заявки и их статусы, повтор заявки, обмен файлами по заявке. Видит только данные своей организации |
| Менеджер | Кабинет менеджера: все заявки, фильтры, назначение ответственного, комментарии, статусы, загрузка PDF-предложения, экспорт CSV. Панель: заявки, организации, сообщения (без изменения каталога) |
| Администратор | Панель: каталог, характеристики, тарифы, контент, пользователи, роли, блокировка, редиректы, импорт CSV, webhook, журнал действий |

Изоляция: все клиентские запросы фильтруются по `organization_id` пользователя; объекты адресуются UUID; файлы отдаются только через проверку прав. Проверяется автотестом на двух организациях (критерий «Разделение доступа», ТЗ 6).

## 4. Данные

Основные сущности (35 таблиц): `users`, `sessions`, `organizations`; `categories` (2 уровня), `manufacturers`, `availability_statuses`, `attribute_definitions` + `attribute_options` (словарь характеристик: число / строка / да-нет / выбор), `attribute_values`, `equipment`, `equipment_images`, `tariffs`, `extra_services`, `pricing_settings`; `pages`, `services`, `projects`, `publications`, `site_settings`, `redirects`; `inquiries`, `inquiry_items`, `inquiry_extra_services`, `inquiry_status_history`, `inquiry_comments`, `attachments`, `contact_messages`; `import_jobs`, `webhook_endpoints`, `outbox`, `webhook_deliveries`; `audit_log`.

Карточка техники (ТЗ 2.2): название, категория, производитель, модель, год, характеристики (из словаря, редактируется администратором), изображения, статус доступности (словарь), условия аренды, тариф за смену и за сутки, флаг «скрыть цену» (тогда — «запросить предложение»), SEO-поля.

## 5. Сценарии

**С1. Подбор и заявка (посетитель).** Каталог → фильтры (категория, производитель, доступность, характеристики) и поиск по названию/модели → карточка → «В заявку» (до 10 позиций) → `/request`: период, место, доп. услуги, контакты, согласие на обработку ПДн → предварительный расчёт обновляется автоматически → отправка → номер `DT-000123`, подтверждение на экране и на email; менеджерам — письмо и webhook.

**С2. Обработка заявки (менеджер).** Кабинет → список с фильтрами (статус, ответственный, организация, даты, поиск) → деталь: состав, расчёт, контакты, файлы → назначить ответственного → комментарий (внутренний или клиенту) → смена статуса (история сохраняется) → загрузка PDF-предложения → статус «Предложение направлено» (клиент получает письмо) → «Согласована» → «Завершена». Экспорт списка в CSV.

**С3. Кабинет клиента.** Регистрация по email с подтверждением → профиль организации (ИНН, КПП, адрес, контакты) → заявки из кабинета привязываются к организации → история и статусы → повтор заявки → загрузка документов по заявке (pdf/doc/docx/xls/xlsx/jpg/png, ≤20 МБ) → скачивание предложения менеджера.

## 6. Статусы заявки (ТЗ 3.3)

`Новая → Уточнение → Предложение направлено → Согласована → Завершена`, из любого активного — `Отменена`; из «Отменена» администратор может вернуть в «Новая». Каждый переход пишется в историю с автором и комментарием.

## 7. Предварительный расчёт (ТЗ 3.2) — на согласование

- Тарифы вводит администратор: цена за смену (по умолчанию 8 ч) и за сутки, минимальное число смен/суток.
- Для каждой позиции: `стоимость = цена × max(количество смен или суток, минимум) × количество единиц`. Число смен/суток по умолчанию = календарные дни периода включительно, пользователь может изменить.
- Дополнительные услуги — фиксированная сумма за заявку (например, доставка, услуги машиниста).
- Округление каждой строки и итога — до шага (1, 10 или 100 ₽), настраивается; метод — математическое округление.
- Если у техники нет тарифа или включён флаг «скрыть цену» — строка «по запросу», итог показывается как «от N ₽».
- Пометка о НДС и текст оговорки настраиваются. Расчёт сохраняется в заявке как снимок, последующее изменение тарифов его не меняет.

**Вопросы Заказчику:** считать ли смены по календарным дням или только рабочим; нужен ли коэффициент за ночную смену/выходные; НДС в тарифах включён или нет.

## 8. Обмен данными (ТЗ 5.1)

- **CSV-импорт каталога**: UTF-8, разделитель `;`, колонки по шаблону `docs/CSV_TEMPLATE.md`; ключ — `external_id` (повторный импорт обновляет, не дублирует); режим «только проверка»; отчёт об ошибках по строкам.
- **CSV-экспорт заявок**: из кабинета менеджера с текущими фильтрами.
- **Email**: через SMTP Заказчика; 5 шаблонов (подтверждение email, сброс пароля, заявка принята — клиенту, новая заявка — менеджерам, смена статуса — клиенту).
- **Webhook** `inquiry.created`: POST JSON с подписью HMAC-SHA256 (`X-Dortech-Signature`), повторы при недоступности приёмника. Формат — `docs/WEBHOOK.md`.

## 9. Инфраструктура (ТЗ 5.4–5.5)

Два окружения (test с basic-auth и `noindex`, prod), HTTPS и HSTS, секреты только в `.env`, журнал ошибок приложения с ротацией, ежедневный `pg_dump` с проверкой восстановления, ЧПУ-адреса, настраиваемые метаданные, `sitemap.xml`, `robots.txt`, редиректы из панели. Требования к серверу: 4 vCPU, 8 ГБ, SSD, Ubuntu 24.04, Docker.

## 10. Контрольные размеры экрана (ТЗ 2.4)

360 px (мобильный: одноколоночная сетка, фильтры в шторке, таблицы превращаются в карточки), 768 px (две колонки), 1440 px (контейнер 1440, четыре колонки каталога, фильтры слева). Горизонтальной прокрутки основного содержимого нет; проверяется автотестом Playwright.
